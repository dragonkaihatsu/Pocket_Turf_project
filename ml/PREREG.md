# LightGBM 検証の事前登録

**このファイルは結果を1つも見る前に書き、先に commit する。**
理由は、結果を見てから基準を動かせないようにするため。以下に書いていない
指標・分割・戦略を、あとから足して「良かったもの」を報告しない。

作成: 2026-09-06 / 対象: 中央（JRA）9-12R・2023〜2026年

---

## 1. 何を確かめるのか

これまでの実測で、中央は**どう切っても回収率77〜81%に収束**した。
スコアリングは市場の劣化版（スコア1位の勝率15.7% 対 1番人気30.8%）で、
「予測精度を上げても回収率は上がらない」が5例確認されている。

そこで問いを**1つだけ**に絞る。

> **勾配ブースティングは、単勝オッズが持っていない情報を見つけられるか。**

「当たるモデルを作れるか」ではない。**市場より当たるか**である。
当てるだけなら人気順で足りる（1番人気の複勝率62.8%）。

## 2. データと分割（時系列。ランダム分割はしない）

| 用途 | 期間 | 使い方 |
|---|---|---|
| 学習 | 2023-01 〜 2024-08 | 木を育てる |
| 早期打ち切り | 2024-09 〜 2024-12 | 木の本数を決める。ここだけ |
| **検証** | **2025年** | **買い方を1つ選ぶ。ここまでは何度見てもよい** |
| **試験** | **2026年** | **最後に1回だけ測る。選び直しはしない** |

- ランダム分割は使わない。同じ開催日の馬が学習と検証に分かれると、
  レース内の情報が漏れて成績が実際より良く出る
- 早期打ち切りを検証年でやらない。木の本数を決めるのに使った年で
  買い方も決めると、検証年に二重に合わせることになる

## 3. 特徴量（3セットを必ず並べる）

| セット | 中身 | この比較で分かること |
|---|---|---|
| **A 市場なし** | オッズ・人気を**入れない**。馬・騎手・血統・条件・過去成績のみ | モデルが市場と独立に持っている情報の量 |
| **B 市場あり** | A ＋ log(単勝オッズ) ＋ 人気 | 市場に情報を足せているか |
| **C 対照** | **人気順のみ**（モデルを使わない） | 市場そのもの |

- **B が C を上回らなければ、モデルは市場を作り直しただけ**である
- A が C に遠く及ばないのは想定内。A の意味は「市場抜きでどこまで行けるか」

### 使う列（すべて発走前に分かるものだけ）
出走馬CSV: 馬番 枠番 性別 年齢 斤量 脚質 馬体重 馬体重増減 前走着順
前走間隔日数 上がり3F 転入初戦 長期休養明け 直近3走JRA数 騎手 血統父 血統母父
race_info: 距離 馬場種別 馬場 天候 頭数 クラス 斤量条件 格 開催場
自作履歴（収集済みレースのうち**当該レース日より前**のみ）: 出走数 着内率
平均着順 当該場の着内率 当該距離帯の着内率

### 意図的に入れないもの
- 4角通過順・タイム・着差（**発走後にしか分からない**）
- 目的変数から作った統計量（騎手の着内率などのターゲットエンコーディング）。
  高カーディナリティの列は LightGBM のカテゴリ機能でそのまま渡す

## 4. 目的変数

**着内（3着以内）= 1 / それ以外 = 0** の二値。
ワイド・馬連の買い目に直接つながる形にする。
勝ち馬モデルは作らない（作れば「良かった方」を選べてしまう）。

## 5. 評価（ここが本体）

**AUC や正解率は補助情報としてしか見ない。判断は回収率で行う。**

各レースでモデルの確率順に並べ、以下の**4つだけ**を測る。
これ以外の買い方は追加しない。

1. 馬連 上位4頭BOX（6点）
2. 馬連 上位5頭BOX（10点）
3. ワイド 上位3頭BOX（3点）
4. ワイド 上位4頭BOX（6点）

同じ4つを**人気順（対照C）でも測って必ず併記**する。

- 1点100円。ブートストラップ1万回で90%信頼区間と100%超の確率を出す
- **高配当は除かない**。競馬の払戻は確率の逆数なので、除けば体系的に下振れする
- すべての率に母数を併記する

## 6. 事前に固定するもの

ハイパーパラメータは以下で固定し、**探索しない**。
（探索すれば必ず「良い組み合わせ」が見つかるが、それは検証年への当てはめである）

    objective=binary, learning_rate=0.05, num_leaves=31,
    min_data_in_leaf=200, feature_fraction=0.8,
    bagging_fraction=0.8, bagging_freq=1, lambda_l2=10.0,
    早期打ち切り 100ラウンド, 最大3000ラウンド, seed=0

- min_data_in_leaf を大きめ(200)に取るのは、騎手・血統のような
  カーディナリティの高い列で葉が数頭に張り付くのを防ぐため

## 7. 過学習・認知の歪みへの対策（この検証で守ること）

| 歪み | 対策 |
|---|---|
| 未来の情報が混じる | 時系列分割。履歴は必ず当該レース日より前だけ |
| 検証年に合わせ込む | 試験年(2026)は最後に**1回**。選び直しをしない |
| 多重比較 | 測る構成を **3セット × 4戦略 = 12** に固定し、実際に見た数を報告に明記する |
| 良い年だけ見る | 検証年と試験年を**必ず両方**載せる。片方だけ良ければ「再現しなかった」と書く |
| 生存者バイアス | 高配当を除かない。全レースを機械的に買った数字を出す |
| 「当たる＝儲かる」の混同 | 的中率と回収率を分けて載せる。判断は回収率 |
| 母数の錯覚 | すべての率に n を書く |
| 沈没費用 | **空振りならそのまま空振りと書く**。使い道を探さない |

## 8. 「効かなかった」の定義（先に決めておく）

以下のいずれかなら、**LightGBM は中央では効かなかった**と結論する。
あとから条件を緩めない。

- 試験年(2026)で **B が C を上回らない**（4戦略のうち3つ以上で下回る）
- または、B の回収率が **どの戦略でも100%に届かない**
- または、検証年で良かった戦略が試験年で**符号反転**する
  （今セッションだけで3例あった形）

逆に「効いた」と言えるのは、**検証年と試験年の両方で B が C を上回り、
かつ試験年の90%信頼区間の下限が払戻率(77.5%)を超える**場合に限る。

## 9. 想定される結末

正直に書いておく。**空振りの見込みが高い。**
中央は2年分の実測でどう切っても77〜81%に収束しており、その原因は
「スコアが悪い」ではなく「市場が効率的」である可能性が高い。
モデルを変えても市場効率は変わらない。

それでも測る理由は、**確かめずに諦めるのと、確かめて諦めるのは違う**から。
空振りなら空振りとしてここに記録し、同じ仮説を繰り返し検討しないで済むようにする。
